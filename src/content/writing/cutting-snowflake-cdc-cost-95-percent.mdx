In April 2026, we cut over our production Change Data Capture (CDC) pipeline streaming **436 SQL Server tables** into a **493-table Snowflake Bronze layer** using **Debezium + Kafka (Strimzi on Kubernetes / AKS)** provisioned with **Terraform, Helm, and GitHub Actions**.

Here is how we cut Snowflake ingestion spend by **~95%**, eliminated multi-day restart gaps, and delivered a zero-leak enterprise CDC feed to **Siemens**.

## 1. Replacing ~48-Credit/Day Per-Record MERGEs with Batched Drains

Running per-record `MERGE` queries as CDC events arrived kept the Snowflake warehouse active continuously, burning **~48 credits/day**.

We replaced per-record merges with a batched drain architecture:

- **Scheduled Drain Windows & Batched MERGEs**: Buffered CDC events and applied **batched MERGEs** during scheduled drain windows, loading **500K+ rows per run in about an hour**.
- **Auto-Suspending Warehouse, Retries & DLQ**: Paired batched execution with an **auto-suspending warehouse**, automated **retries**, and a **dead-letter queue (DLQ)**—cutting Snowflake ingestion spend by **~95%**.

```sql
-- Representative pattern: batched MERGE deduplicated by LSN per drain window
MERGE INTO bronze.dbo_orders AS tgt
USING (
  SELECT *
  FROM bronze_staging.raw_cdc_events
  QUALIFY ROW_NUMBER() OVER (
    PARTITION BY id
    ORDER BY __source_lsn DESC, __seqval DESC
  ) = 1
) AS src
ON tgt.id = src.id
WHEN MATCHED AND src.__op = 'd' THEN DELETE
WHEN MATCHED THEN UPDATE SET tgt.record = src.payload, tgt.last_lsn = src.__source_lsn
WHEN NOT MATCHED AND src.__op != 'd' THEN INSERT (id, record, last_lsn)
  VALUES (src.id, src.payload, src.__source_lsn);
```

## 2. Stopping Multi-Day Sync Gaps After AKS & SQL Server Restarts

Previously, AKS node restarts and SQL Server maintenance caused multi-day CDC sync gaps. After leading recovery from a cluster incident, we hardened pipeline reliability with three changes:

- **Debezium Connector Auto-Restart**: Enabled automatic connector task restarts after transient infrastructure resets.
- **15-Minute Lag & Dead-Letter Watchdog**: Added a watchdog alerting on replication lag or dead-letter queue accumulation within 15 minutes.
- **Fail-Closed Production Deploys**: Configured CI/CD deployments to fail closed when connector or offset checks fail.

## 3. Siemens 74-Table CDC Cutover & SQL Server Dynamic Data Masking

- **Siemens CDC Feed**: Took **Siemens** live on a Snowflake-to-Snowflake CDC feed of **74 tables (~2.1M-row initial snapshot, changes applied twice daily)** without exposing internal pricing by withholding pricing columns, locking Siemens to a **negative-tested read-only role** with no export path, and leading the production cutover.
- **Source Data Security**: Protected **18 sensitive SQL Server tables** (*customer, order, invoice, pricing, vendor*) using dynamic data masking with role-tiered `UNMASK` grants.
