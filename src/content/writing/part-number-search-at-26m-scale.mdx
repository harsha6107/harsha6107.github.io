Default full-text analyzers split on punctuation and rank by prose term frequency. In a **26M-document industrial product catalog** where **~77% of SKUs contain slashes**, default tokenization breaks exact and partial part-number lookups.

Here is how we rebuilt both the sync pipeline and relevance ranking for Peregrin's Elasticsearch index.

## 1. Fixing Silent Record Loss in the 26M-Document Sync

Before tuning ranking, every SKU in the catalog had to reach the index reliably. Root-causing missing products exposed **6 defects** in the legacy sync—including batch jobs sending **70K+ SKUs in a single bulk call**, offset pagination bottlenecks, unhandled bulk item errors, and unverified alias swaps.

We rebuilt the pipeline with five guarantees:

- **Keyset Pagination**: Replaced offset scans with deterministic keyset cursors.
- **Bounded Bulk Chunks**: Capped bulk requests at **~1,000 documents / 5 MB**.
- **2x Write Concurrency & 15-Minute Deltas**: Doubled write concurrency and scheduled incremental delta syncs every **15 minutes**.
- **Alias Swaps with Count Checks**: Verified document counts on staging indices before switching production read aliases.
- **Target Catalog-Sync Architecture**: Designed the target architecture to eliminate write backpressure and multi-writer overwrites using **Azure Service Bus**, the **outbox pattern**, **bounded-concurrency workers**, and **field-level ownership with partial updates**.

## 2. Tiered Matching for the ~77% of SKUs with Slashes

To make part-number search tolerant of punctuation and typos across the **~77% of SKUs containing slashes**, we shipped **tiered exact / normalized / prefix / fuzzy matching** paired with **part-number-first ranking and popularity tie-breaks**:

```json
{
  "settings": {
    "analysis": {
      "char_filter": {
        "strip_delimiters": {
          "type": "pattern_replace",
          "pattern": "[^a-zA-Z0-9]",
          "replacement": ""
        }
      },
      "normalizer": {
        "sku_exact": {
          "type": "custom",
          "filter": ["lowercase", "asciifolding"]
        }
      },
      "analyzer": {
        "sku_normalized": {
          "tokenizer": "keyword",
          "char_filter": ["strip_delimiters"],
          "filter": ["lowercase"]
        }
      }
    }
  }
}
```

1. **Exact Match**: Matches the case-folded part number with slashes and hyphens intact.
2. **Normalized Match**: Strips slashes and delimiters so queries with or without punctuation resolve to the same SKU.
3. **Prefix Match**: Supports incremental part-number lookup as buyers type.
4. **Fuzzy Match + Popularity Tie-Breaks**: Recovers from typos while ranking part-number matches first and breaking ties by popularity.

## 3. Cutting Aggregations from 100,000 to 500 Buckets

Search queries previously requested **100,000 buckets** per facet aggregation. Reducing aggregation size from **100,000 to 500 buckets** cut per-query bucket overhead by **99.5%** while preserving relevant facet filters.
