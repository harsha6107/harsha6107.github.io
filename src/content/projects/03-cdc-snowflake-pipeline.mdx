## Problem & Operational Bottlenecks

Streaming **436 production SQL Server tables** into a **493-table Snowflake Bronze layer** faced three challenges prior to our **04/2026 production cutover**:

1. **High Compute Cost (~48 Credits/Day)**: Per-record `MERGE` queries kept the Snowflake warehouse running continuously.
2. **Multi-Day Sync Gaps**: AKS and SQL Server restarts left Debezium connectors wedged for days without automated recovery.
3. **Enterprise Data Isolation**: Onboarding **Siemens** required a Snowflake-to-Snowflake CDC feed of **74 tables (~2.1M-row initial snapshot, updated twice daily)** without exposing internal pricing.

## Architectural Approach

### 1. Debezium + Kafka (Strimzi on AKS) & Reliability Guards

I led the **Debezium + Kafka (Strimzi on Kubernetes / AKS)** pipeline provisioned with **Terraform, Helm, and GitHub Actions**, and led recovery from a subsequent cluster incident:

- **Connector Auto-Restart**: Enabled Debezium connector auto-restart to recover automatically after AKS and SQL Server restarts.
- **15-Minute Lag & Dead-Letter Watchdog**: Added a 15-minute lag and dead-letter queue (DLQ) watchdog to catch stalled tasks early.
- **Fail-Closed Deploys**: Configured production deployments to fail closed if health or offset checks fail.

### 2. Cutting Snowflake Ingestion Spend ~95%

I replaced per-record `MERGE` statements (**~48 credits/day** of always-on compute) with **batched MERGEs**, **scheduled drain windows**, an **auto-suspending warehouse**, **retries**, and a **dead-letter queue**—loading **500K+ rows per run in about an hour** while cutting Snowflake ingestion spend by **~95%**:

```sql
-- Representative pattern: batched MERGE during a scheduled drain window
MERGE INTO bronze.orders AS target
USING (
  SELECT *
  FROM staging.orders_cdc_batch
  QUALIFY ROW_NUMBER() OVER (
    PARTITION BY order_id
    ORDER BY __source_lsn DESC, __seqval DESC
  ) = 1
) AS src
ON target.order_id = src.order_id
WHEN MATCHED AND src.__op = 'd' THEN DELETE
WHEN MATCHED THEN UPDATE SET
  target.status = src.status,
  target.updated_at = src.updated_at,
  target.__cdc_lsn = src.__source_lsn
WHEN NOT MATCHED AND src.__op != 'd' THEN INSERT (order_id, status, updated_at, __cdc_lsn)
  VALUES (src.order_id, src.status, src.updated_at, src.__source_lsn);
```

### 3. Siemens 74-Table CDC Cutover & SQL Server Dynamic Data Masking

- **Siemens Snowflake-to-Snowflake CDC Feed**: Took Siemens live on **74 tables (~2.1M-row initial snapshot, changes applied twice daily)** without exposing internal pricing by withholding pricing columns, locking Siemens to a **negative-tested read-only role** with no export path, and leading the production cutover.
- **SQL Server Dynamic Data Masking**: Protected **18 sensitive tables** (*customer, order, invoice, pricing, vendor*) by designing SQL Server dynamic data masking with role-tiered `UNMASK` grants.
