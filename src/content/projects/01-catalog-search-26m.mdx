## Context & Failure Modes

Industrial procurement Buyers do not search like consumer e-commerce shoppers. When an maintenance engineer or distributor buyer searches a **26-million-SKU catalog**, they paste partial manufacturer part numbers (`6204-2RS/C3`), slash-delimited fractional dimensions (`3/8"-16 UNC`), or OCR-scanned strings with missing delimiters (`62042RSC3`).

When I took ownership of the Peregrin search data platform and relevance engine, two systemic problems threatened customer trust:

1. **Silent Record Loss in the 26M-Document Sync Pipeline**: Full index rebuilds and incremental syncs periodically dropped thousands of SKUs without alerting. Root-causing the pipeline exposed **6 distinct defects**, including a single bulk indexing call attempting to push **70,000+ SKUs in one payload**, deep `OFFSET` pagination timeouts on source tables, silent partial failures inside Elasticsearch `_bulk` responses, and unverified index alias swaps.
2. **Punctuation Blindness & 100K-Bucket Heap Pressure**: Roughly **77% of SKUs in the catalog contain forward slashes (`/`)**. Standard tokenization split part numbers across slash boundaries, causing exact part lookups to rank behind generic description matches. Simultaneously, category and manufacturer facet queries requested `size: 100000` buckets on every search, saturating coordinator node heap memory.

## Architectural Approach

### 1. Rebuilding the 26M-Document Ingestion Pipeline

We tore down offset-based batching and rebuilt the synchronization engine around deterministic boundaries:

```csharp
// Keyset pagination + dual-threshold bulk chunker (~1,000 docs or 5 MB max)
public async Task SyncCatalogPartitionAsync(Guid? lastSkuId, DateTimeOffset watermark, CancellationToken ct)
{
    const int MaxDocsPerChunk = 1000;
    const int MaxBytesPerChunk = 5 * 1024 * 1024; // 5 MB safety ceiling

    while (!ct.IsCancellationRequested)
    {
        var batch = await _catalogRepo.FetchKeysetBatchAsync(lastSkuId, watermark, MaxDocsPerChunk, ct);
        if (batch.Count == 0) break;

        foreach (var payloadChunk in ChunkByByteBudget(batch, MaxBytesPerChunk))
        {
            var response = await _elasticClient.BulkAsync(payloadChunk, ct);
            if (response.Errors)
            {
                await _deadLetterQueue.PublishFailedItemsAsync(response.ItemsWithErrors, ct);
            }
        }
        lastSkuId = batch[^1].SkuId;
    }
}
```

- **Keyset Pagination & 15-Minute Deltas**: Replaced `OFFSET/LIMIT` scans with indexed `(updated_at, sku_id)` keyset cursors, running incremental delta sweeps every 15 minutes at **2x write concurrency**.
- **Count-Gated Blue/Green Alias Swaps**: Full index rebuilds write to a staging index (`catalog_v_next`) with refresh intervals relaxed during bulk load. Before switching the live read alias, a gate verifies `count(staging) >= expected_floor` and zero dead-letter threshold breaches.
- **Target Distributed Catalog-Sync Architecture**: Designed the next-generation event-driven sync using **Azure Service Bus**, the **transactional outbox pattern**, bounded-concurrency workers, and **field-level ownership with partial updates**—eliminating write backpressure and multi-writer overwrites between PIMS catalog feeds and real-time tenant pricing.

### 2. Four-Tier Part-Number Relevance & 500-Bucket Aggregations

To make search resilient to slashes, hyphens, and buyer typos across 26M items, we engineered a multi-field index mapping and a **4-tier bool/dis_max query cascade**:

| Tier | Field Analyzer | Query Strategy | Boost Weight | Target Failure Mode |
| :--- | :--- | :--- | :--- | :--- |
| **Tier 1 — Exact Raw** | `keyword` (case-folded) | `term` match | `12.0x` | Exact copy-pasted SKU with slashes (`6204-2RS/C3`) |
| **Tier 2 — Normalized Alphanumeric** | `pattern_replace` (`[^a-zA-Z0-9] -> ""`) | `term` + `prefix` | `8.5x` | Missing or altered slashes/dashes (`62042RSC3` or `6204 2RS C3`) |
| **Tier 3 — Structural Token Prefix** | Custom `char_filter` preserving `/` splits + `edge_ngram` | `match_phrase_prefix` | `4.0x` | Partial catalog lookup while typing (`6204-2RS`) |
| **Tier 4 — Typo-Tolerant Fuzzy + Spec** | `standard` + `fuzziness: AUTO:4,7` | `multi_match` (`best_fields`) | `1.5x` | Transposed digits or OCR noise + popularity tie-breaker |

- **Part-Number-First Ranking with Popularity Tie-Breaks**: By combining Tier 1–4 scores inside a `function_score` query weighted by historical tenant order frequency (`log1p(order_count)`), common replacement parts surface above obscure sub-assemblies when prefixes collide.
- **Cutting Aggregations from 100,000 to 500 Buckets**: Replaced unbounded 100K-bucket terms aggregations with scoped top-500 bucket aggregations plus targeted filter-context facets, reducing coordinator heap allocation per query by **99.5%** while preserving 100% of visible UI filter utility.
