## Problem & Failure Modes

Peregrin is a multi-tenant procurement and product-catalog SaaS platform for industrial parts distributors. Across a **26M-document Elasticsearch index**, two issues degraded search quality:

1. **Record Loss in Product Sync**: Full rebuilds and incremental syncs dropped products silently. Root-causing the pipeline uncovered **6 defects**, including batch jobs pushing **70K+ SKUs in a single bulk call**, offset pagination bottlenecks, unhandled bulk item errors, and unverified alias switches.
2. **Slash Tokenization & 100K-Bucket Aggregations**: Roughly **77% of SKUs contain slashes**. Standard tokenization split part numbers across punctuation, while facet aggregations requested **100,000 buckets** per query.

## Architectural Approach

### 1. Zero-Loss 26M-Document Sync Pipeline

I rebuilt the Elasticsearch ingestion pipeline around deterministic batching and verification:

```csharp
// Representative pattern: keyset pagination + ~1,000-doc / 5 MB chunking
public async Task SyncCatalogPartitionAsync(Guid? lastSkuId, DateTimeOffset watermark, CancellationToken ct)
{
    const int MaxDocsPerChunk = 1000;
    const int MaxBytesPerChunk = 5 * 1024 * 1024; // 5 MB ceiling

    while (!ct.IsCancellationRequested)
    {
        var batch = await _catalogRepo.FetchKeysetBatchAsync(lastSkuId, watermark, MaxDocsPerChunk, ct);
        if (batch.Count == 0) break;

        foreach (var chunk in ChunkByByteBudget(batch, MaxBytesPerChunk))
        {
            var response = await _elasticClient.BulkAsync(chunk, ct);
            if (response.Errors)
            {
                await _deadLetterQueue.PublishFailedItemsAsync(response.ItemsWithErrors, ct);
            }
        }
        lastSkuId = batch[^1].SkuId;
    }
}
```

- **Keyset Pagination & Bounded Chunks**: Replaced offset scans with keyset pagination and bounded every bulk request to **~1,000 documents / 5 MB** at **2x write concurrency**.
- **15-Minute Deltas & Count-Checked Alias Swaps**: Scheduled incremental delta syncs every **15 minutes** and required document-count checks before swapping blue/green index aliases.
- **Target Distributed Sync Architecture**: Designed the target catalog-sync architecture using **Azure Service Bus**, the **outbox pattern**, **bounded-concurrency workers**, and **field-level ownership with partial updates** to eliminate write backpressure and multi-writer overwrites.

### 2. Tiered Part-Number Relevance & 500-Bucket Aggregations

To handle punctuation and typos across the **~77% of SKUs containing slashes**, I shipped a four-tier matching strategy with **part-number-first ranking** and **popularity tie-breaks**:

| Tier | Matching Strategy | Target Query Pattern |
| :--- | :--- | :--- |
| **Tier 1 — Exact** | Case-folded exact part-number match | Verbatim SKU lookups preserving slashes and hyphens |
| **Tier 2 — Normalized** | Delimiter-stripped alphanumeric match | Queries omitting or altering slashes, dashes, or spaces |
| **Tier 3 — Prefix** | Token and structural prefix matching | Partial part numbers entered during search-as-you-type |
| **Tier 4 — Fuzzy** | Edit-distance fallback + popularity tie-breaks | Typo recovery ranked by part-number priority and order popularity |

- **Cutting Aggregations from 100,000 to 500 Buckets**: Reduced facet aggregation size from **100,000 to 500 buckets**, cutting per-query bucket overhead by **99.5%** without losing relevant filter options.
