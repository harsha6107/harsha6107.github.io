## Problem

1. **Unindexed Spec & Installation Corpus (28 GB)**: Product specifications and installation guides were stored across **~400K database rows** (~35K documents totaling **28 GB**) with heavy duplication and no retrieval layer.
2. **Parts Classification & Lead-Time Estimation**: Catalog parts needed automated classification across **382 ETIM classes** with PIMS writeback, and buyers needed reliable shipping lead-time predictions.

## Architectural Approach

### 1. 28 GB Production RAG Pipeline (~98% Ingestion Success)

I made **~35K product spec and installation documents (28 GB)** answerable by our AI agent at **~98% ingestion success**:

- **Deduplication (~400K → ~29K Files)**: Deduplicated **~400K source rows down to ~29K unique files**.
- **Parallel Migration & Indexing**: Migrated the deduplicated files to **Azure Blob** using parallel workers, indexed them in **Azure AI Search**, and linked agent answers directly to product search.

### 2. 382-Class ETIM Classification Pipeline (21 ms Latency)

I delivered parts classification at **~95% OCR accuracy**, **~92% class-match accuracy across 382 ETIM classes**, and **21 ms latency** by negotiating the SOW with a CMU engineering team (catching IP-term changes, unsupported accuracy targets, and missing deliverables), scoping and directing delivery (OCR, attribute prediction, human review, PIMS writeback), and owning post-handover tuning:

```python
# Representative pattern: confidence routing for 382-class ETIM PIMS writeback
def route_etim_prediction(part_id: str, class_id: str, confidence: float, attrs: dict) -> str:
    if confidence > 0.85:
        pims.writeback(part_id, class_id, attrs)
        return "AUTO_ACCEPT"
    if confidence >= 0.50:
        review_queue.enqueue(part_id, class_id, confidence, attrs)
        return "HUMAN_REVIEW"
    return "REJECT"
```

- **Held-Out Evaluation & Confidence Routing**: Pushed for strict held-out evaluation and confidence routing (**auto-accept above 0.85**, **human review 0.5–0.85**).

### 3. Shipping Lead-Time Prediction (MLflow → Snowflake Days-to-Ship API)

- Framed shipping lead-time prediction as a measurable ML problem (**MAE and P90**) by designing features, labels, and **Random Forest / GBM baselines** tracked in **MLflow**; later productionized by a CMU practicum team as a **Snowflake** model behind a **Days-to-Ship API**.
