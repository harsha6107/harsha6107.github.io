## Context & Dual Unstructured Data Challenges

Industrial parts catalogs suffer from two complementary unstructured data bottlenecks:

1. **Unindexed Technical Manuals (28 GB across ~35K Documents)**: Buyers need exact answers from installation guides and spec sheets (*torque ratings, wiring pinouts, chemical compatibility*), but the source database held **~400,000 attachment rows** with massive duplication, broken links, and zero full-text or semantic indexing.
2. **Unclassified Catalog Additions (382 ETIM Classes)**: Incoming supplier parts arrive as scanned PDFs or sparse descriptions that must be mapped into **382 standardized ETIM technical classes** with structured attribute key-value pairs before they can power faceted search in PIMS.

## Architectural Approach

### 1. Deduplicating 400K Rows into a 28 GB Production RAG Corpus

Rather than naively embedding all 400,000 attachment records, we designed a content-addressed ingestion pipeline:

- **400K → 29K Canonical File Deduplication**: Fingerprinted source URLs and binary streams to collapse **~400,000 source database rows into ~29,000 unique files** while preserving a many-to-many join table mapping every document chunk back to all associated SKU IDs.
- **Parallel Azure Blob Migration & Azure AI Search Indexing**: Migrated **28 GB (~35K spec and installation documents)** into Azure Blob Storage using bounded parallel Python workers, achieving a **~98% end-to-end ingestion success rate**.
- **SKU-Linked Hybrid Retrieval**: Indexed extracted sections in **Azure AI Search** (combining dense vector embeddings with BM25 keyword scoring for exact model numbers) and wired retrieval tools so agent answers cite both the source datasheet page and direct links to the purchasable SKUs in Peregrin's product search.

### 2. 382-Class ETIM Classification at 21 ms Latency

I scoped and directed a Carnegie Mellon University engineering team—and owned post-handover production tuning—to build an end-to-end **ML parts classification pipeline**:

```python
# Confidence-tiered routing policy for 382-class ETIM PIMS writeback
def route_etim_prediction(part_id: str, class_id: str, confidence: float, attrs: dict) -> str:
    if confidence >= 0.85:
        pims_client.writeback_classification(part_id, class_id, attrs, status="AUTO_VERIFIED")
        return "AUTO_ACCEPT"
    elif confidence >= 0.50:
        review_queue.enqueue(part_id, class_id, confidence, attrs, priority="STANDARD")
        return "HUMAN_REVIEW"
    else:
        review_queue.enqueue(part_id, class_id, confidence, attrs, priority="LOW_CONFIDENCE")
        return "REJECT_TO_TRIAGE"
```

- **95% OCR Accuracy & 92% Class Match**: Combined high-speed OCR extraction with a multi-head attribute and class predictor across **382 ETIM classes**, achieving **~95% OCR accuracy**, **~92% class-match accuracy**, and **21 ms inference latency**.
- **Calibrated Confidence Routing**: Enforced held-out evaluation discipline and a three-band routing policy: predictions above `0.85` confidence write back automatically to PIMS, predictions in `0.50–0.85` route to a human-in-the-loop review queue, and sub-`0.50` predictions are quarantined.
- **Shipping Lead-Time Prediction (Days-to-Ship API)**: Applied the same discipline to frame supplier lead-time prediction as a measurable ML problem (**MAE and P90**), designing feature pipelines and Random Forest / GBM baselines tracked in **MLflow** that were subsequently productionized in **Snowflake** behind a real-time **Days-to-Ship API**.
