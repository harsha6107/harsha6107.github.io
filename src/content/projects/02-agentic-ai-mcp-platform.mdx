## Stack Selection & Architecture

I chose the assistant's stack on measured cost and capability by benchmarking **Azure AI Foundry** against **LangGraph, CrewAI, and AutoGen**, then hardened it with RBAC/ReBAC test scenarios, security standards, and token and latency optimization.

## Core System Components

### 1. 42-Tool Production Assistant & Grounding Fixes

I shipped the agentic AI assistant to production users and a customer beta—scoring **25/25 on a golden evaluation set**—by building **42 strict function-calling tools** on Azure AI Foundry with:

- **Relationship-Based Access Control (ReBAC)**: Configured ReBAC with **Permit** and closed a cross-workspace authorization gap among ~15 production bugs fixed in one release cycle.
- **Signed 5-Minute Action Tokens**: Write tools stage changes and return a **signed 5-minute action token** requiring explicit human-in-the-loop confirmation before execution, paired with query logging and user feedback.
- **Production Grounding & Context Precedence**: Removed a chat BOM import that never reached the model and caused a High-priority production bug (items added to the wrong project); scoped *"my orders"* to the user's own POs; made the open page outrank conversation memory; and added read-only CSV/XLSX attachments with a row-search tool that treats file content as untrusted.

```typescript
// Representative pattern: ReBAC check + signed 5-minute action token for user-confirmed writes
export async function stageWriteAction<T>(
  ctx: AuthContext,
  toolName: string,
  payload: T,
): Promise<StagedActionResponse<T>> {
  const allowed = await permit.check(ctx.userId, 'write', {
    type: 'project',
    key: ctx.activeProjectId,
    tenant: ctx.tenantId,
  });
  if (!allowed) throw new ForbiddenError('Unauthorized workspace write');

  const expiresAt = Date.now() + 5 * 60 * 1000; // 5-minute TTL
  const token = signActionToken({ userId: ctx.userId, toolName, payload, expiresAt });

  return { status: 'CONFIRMATION_REQUIRED', actionToken: token, preview: payload };
}
```

### 2. Stateless 36-Tool MCP Server, Browser Agent & Claude Code Harness

- **Model Context Protocol (MCP)**: Made Peregrin usable from **Claude, ChatGPT, and VS Code** by building a **stateless MCP server** (**36 tools, 156 tests, OAuth 2.1**) with endpoint-matched permissions and audited, user-confirmed writes.
- **Browser Extension Agent**: Automated supplier price research for buyers by building a **TypeScript Chrome/Edge extension agent** that searches supplier portals, ranks offers by price, and adds parts to projects while trimming page context to fit LLM token budgets.
- **AI-Assisted Development Standards**: Authored the **Claude Code developer guide** and built the team's agent harness (context-optimized docs, skills, subagents, validators, and hooks).

### 3. Company Knowledge Layer (eParts Brain) & Continuous Eval Loop

- **eParts Brain**: Designed one search layer so engineers and Claude agents can find past decisions across **Granola, Linear, GitHub, and Confluence**: hash-merged incremental ingestion into Snowflake, **Cortex Search hybrid retrieval** behind Snowflake's managed MCP server, role-tiered access, secret scanning on ingest, and a weekly top-5 retrieval eval for **~$15–30/month**.
- **Eval & Error-Discovery Loop**: Built the post-launch evaluation pipeline exporting **~100 redacted conversations per cycle** for error analysis, mapping a failure-mode taxonomy to golden cases, checking an **LLM rubric judge** against human labels, and enforcing a **weekly CI eval gate** on agent PRs.
