## Context & Architectural Selection

Before writing production agent code, I benchmarked **Azure AI Foundry** against **LangGraph, CrewAI, and AutoGen** across four operational dimensions: tool-call schema determinism, P95 turn latency, per-conversation token cost, and enterprise RBAC/ReBAC composability.

Multi-agent orchestration frameworks introduced unnecessary hop latency and opaque prompt state for deterministic B2B procurement workflows. We chose a **single-orchestrator, strict tool-calling architecture on Azure AI Foundry** paired with a **stateless Model Context Protocol (MCP) server**, sharing a unified permission and audit core.

## Core System Design

### 1. 42 Strict Function-Calling Tools with Permit ReBAC & Signed 5-Minute Action Tokens

Every tool exposed to the LLM is classified as either `READ_SAFE` or `WRITE_GUARDED`:

- **Relationship-Based Access Control (ReBAC)**: Before any tool executes, the caller's identity and active workspace relationship are verified against **Permit** (`user -> member_of -> workspace -> owns -> purchase_order`). Furthermore, queries like *"show my orders"* are deterministically scoped at the data-access layer to the authenticated user's own POs.
- **Two-Phase Cryptographic Write Confirmation**: When the model invokes any write tool (e.g., `add_bom_items_to_project`, `create_rfq_draft`), the tool does **not** mutate the database. Instead, it validates permissions, computes a dry-run diff, and returns a **signed 5-minute HMAC action token** (`act_tok_...`) to the UI card. The mutation only commits when the human user clicks **Confirm**, submitting the signed token directly to the backend verification endpoint.

```typescript
// Two-phase human-in-the-loop write token issuance (MCP & Foundry shared guard)
export async function stageGuardedWrite<TPayload>(
  ctx: AgentAuthContext,
  toolName: string,
  payload: TPayload,
): Promise<StagedWriteResponse<TPayload>> {
  const allowed = await permit.check(ctx.userId, 'write', {
    type: 'project',
    key: ctx.activeProjectId,
    tenant: ctx.tenantId,
  });
  if (!allowed) {
    throw new ForbiddenToolError(`User ${ctx.userId} lacks write access on ${ctx.activeProjectId}`);
  }

  const expiresAt = Date.now() + 5 * 60 * 1000; // 5-minute TTL
  const payloadHash = sha256Canonical(JSON.stringify({ toolName, payload, expiresAt, sub: ctx.userId }));
  const signature = hmacSign(payloadHash, process.env.ACTION_TOKEN_SECRET!);

  return {
    status: 'CONFIRMATION_REQUIRED',
    actionToken: `${expiresAt}.${ payloadHash }.${signature}`,
    previewDiff: buildHumanReadableDiff(toolName, payload),
  };
}
```

### 2. Stateless 36-Tool OAuth 2.1 MCP Server

To make Peregrin native inside **Claude Desktop/Web, ChatGPT, and VS Code**, I built a **stateless MCP server** exposing **36 tools** backed by **156 automated tests**:

- **OAuth 2.1 with PKCE & Endpoint-Matched Scopes**: External MCP clients authenticate via OAuth 2.1. Each MCP tool maps 1:1 to the underlying REST API's permission matrix, ensuring an external agent can never bypass application-tier authorization.
- **Browser Extension Agent**: Complemented the server-side platform with a **TypeScript Chrome/Edge browser extension agent** that automates supplier portal price research, distilling live DOM trees to fit strict LLM token budgets and ranking offers by landed cost.

### 3. Grounding & The Continuous Eval Loop

- **Company Knowledge Layer (eParts Brain)**: Designed a unified internal retrieval layer across **Granola meeting notes, Linear issues, GitHub PRs, and Confluence pages** using hash-merged incremental ingestion into Snowflake and **Cortex Search hybrid retrieval** behind Snowflake's managed MCP server—complete with secret scanning on ingest and a weekly top-5 retrieval eval at **~$15–30/month**.
- **From 25/25 Golden Set to Continuous Error Discovery**: Designed the post-launch evaluation loop that exports **~100 PII-redacted production conversations per cycle**, categorizes failure modes into a structured taxonomy mapped to golden regression cases, calibrates an **LLM rubric judge** against human annotations, and runs a **weekly CI eval gate** on every chatbot pull request.
